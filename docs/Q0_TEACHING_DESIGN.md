# Q0 新教法设计：先读后答（read-then-answer）

> 目标：教会模型“从状态摘要里读一个可变字段，再重复出来”。
> 针对的失败：s900 的 Q0 仍是 0/7，最小对子（240 条）没修好它。
> 适用：gated v5（d1024，recipe generalist-v5），下一块 chunk 5（s1200 → s1500）。

## 2. 成因：模型从来没学会“读一个可变字段再重复出来”

### 2.1 信息明明就在输入里，模型还是不抄

寄存器格式（`register_format_records.jsonl`，220 条）已经把答案的地点句原样放在提示最前面：

```
你在花果山。
世界状态。……你在花果山。
你在什么地方。你在花果山。
```

答案“你在花果山。”在输入里出现了**两次**（寄存器行 + 摘要里），s900 的 Q0 register 还是 0/7。缺的不是信息的位置，也不是信息的多少——缺的是“抄”这个操作本身。模型根本不做“从输入里读一个字段、原样重复到输出”这件事。

### 2.2 根因：loss 被模板稀释，答案只占约 5%

训练的真实结构（已核对代码，不是推测）：

- 世界域记录由 `training/dataset.py` 的 `_read_world_records` 读出：每条只取 `text` 字段，用 `"\n"` 拼成**一条长文本**。
- `make_batch_fn` 从这条长文本里随机取 128-token 窗口，loss 是标准因果语言模型 loss，**每个 token 都算**。
- 每条记录都有 `answer_start` 字段（答案从第几个字符开始），但**两个训练器都不用它**：`generalist_pilot_train.py`（NumPy）和 `training/dataset.py`（PyTorch）里都没有对 `answer_start` 的引用，没有答案区 loss 掩码。

算一笔账：一条 Q0 记录约 130 个字符，答案“你在花果山。”约 6 个 token，占 128-token 窗口的约 5%。摘要模板（“世界状态。在场人物……可见物品……随身物品……时间第……步……”）占大头，而且模板高度可预测、loss 降得最快。模型的最优解是：**固定默认地点 + 模板满分**。答案 token 的那点 loss，不值得它去学一个抄操作。

### 2.3 为什么最小对子失败

最小对子（2026-11-20 生成，脚本 `~/workspace/dual_sft/build_minimal_pairs.py`，240 条，0 OOV）：

- Q0 最小对 70 条（10 底本 × 7 地点）、Q2 30 条、Q3 20 条，各配寄存器格式；探针格式 602→722 条，地点寄存器 150→220 条，随身寄存器 151→181 条，昼夜寄存器 151→171 条；世界域 439,186 字。
- 原理：同一底本只改一个字段，答案随之变；模型若输出固定答案，7 个变体里 6 个错，梯度逼它读那个字段。

它只改了**数据值**，没改 loss 结构，也没改任务结构：

- **loss 结构没变**：答案 token 还是只占约 5%，固定答案在 6/7 的变体里错，每个变体只丢几个答案 token 的 loss，总代价很小。模型宁可交这点 loss，也不学抄。
- **任务结构没变**：模型仍被要求“默默地”从摘要里抄——抄这个操作本身没有任何显式监督，梯度只能间接地、通过答案 token 的对错传回来。
- 第 3 块的数据混合一变，各地点的边际频率跟着变，最便宜的固定默认就从流沙河挪到了南海。最小对子的梯度信号真实存在，但太弱、太间接，装不上一个抄操作。

**结论：Q0 的问题不在数据量，也不在数据多样性，在 loss 结构和任务结构。** 再加同类数据（更多最小对子、更多模板）是同一条路的重复，不会修好它。

## 3. 新教法：先读后答（read-then-answer）

核心：把“抄”变成一个**显式的、有监督的步骤**，并且让 loss **只盯着答案区**。两个耦合改动，缺一不可。

### 改动 A：答案区 loss（代码改动，修信号）

- 用记录里已有的 `answer_start` 字段做 loss 掩码：答案区之前的 token 不计 loss（label 记为 -100，只算答案区）。
- 实现位置：`training/dataset.py`（世界域记录保留答案区边界，batch 附带答案掩码）+ trainer 的 loss（忽略掩码外位置）。非世界域保持全序列 loss（它们是通用文本，不是问答）。
- 效果：世界域记录上 100% 的梯度推答案行为，而不是约 5%。这是最小对子失败的根因修复，没有它，改动 B 的抽取步也会被模板稀释掉。

### 改动 B：先读后答的记录格式（数据改动，修任务结构）

三类新记录（Q0/Q3 为主，Q2 为辅，Q1 只做少量泛化演练）：

**（1）抽取演练（drills）：只练抄，不练问答。**

prompt 是摘要 + 一个“读字段”的短问，answer 只有字段值本身：

```
世界状态。在场人物孙悟空、唐僧、猪八戒、沙僧、白龙马。可见物品蟠桃、金箍棒。随身物品无。时间第二步白天。你在花果山。
地点是哪里。花果山。
```

```
世界状态。……时间第二步白天。你在花果山。
昼夜是白天还是夜晚。白天。
```

答案只有 2–4 个字，配合答案区 loss，100% 的梯度都在“读摘要、抄字段”这个操作上。问法与探针问题不同（“地点是哪里” vs “你在什么地方”），练的是通用技能，不是某道题的映射。

**（2）带抽取前缀的问答（scaffolded Q&A）：先抄，再答。**

Q0/Q3 的答案前加裸字段值作抽取步：

```
……你在什么地方。花果山。你在花果山。
……现在是白天还是夜晚。白天。现在是白天。
```

模型先写出字段值（抄），再写完整答案（用刚写出的值）。抽取步把**远距离抄**（从几十个 token 外的摘要里抄）变成**近距离抄**（从自己刚生成的 token 里抄），后者容易得多。这就是“先读后答”的字面意思。

**（3）直接问答（direct Q&A）：迁移对照，不加支架。**

探针是直接问的，模型必须在没有支架时也能答。直接问答与支架问答混训，防止模型只会带支架答。直接问答用新模板，避免与旧记录重复。

**格式兼容（已核对判分逻辑）：**

- 抽取前缀只含真实字段值，不含其他地点/昼夜词。核对 `evaluation/scoring.py` 的 `score()`：Q0 只要续文含“你在{真地点}”且不含“你在{他地点}”即过（或含真地点名且不含任何他地点名）；Q3 只要含真昼夜且不含另一昼夜即过。支架格式（“花果山。你在花果山。”、“白天。现在是白天。”）两条都放行。
- Q1 不加支架：答案本身（人物表）已超 16 token 生成预算，且 Q1 已是 3/3，不动它。
- Q2 支架只做随身非空情形（空随身已是 3/3，支架是“无。随身物品无。”，不引入新物品名，避免误提他物品判错）。

## 4. 与最小对子的关键不同

|  | 最小对子（已失败） | 先读后答（本设计） |
|---|---|---|
| 改的是什么 | 数据值：换一个字段，答案跟着变 | 任务结构 + loss 结构：显式抽取步 + 答案区掩码 |
| 抄操作有没有显式监督 | 没有。模型要自己悟出“抄” | 有。抽取演练的答案就是字段值本身；支架问答先抄再答 |
| 答案 token 占 loss 的比例 | 约 5%，被模板稀释 | 100%（答案区掩码后） |
| 问的问题 | “模型能不能在答案变来变去时跟上” | “模型能不能先把字段值抄出来再答” |
| 失败时的表现 | 固定默认换一个（流沙河→南海） | 若仍失败，说明瓶颈不在教法（见 §6） |

一句话：**最小对子是间接逼，新教法是直接教。** 最小对子假设模型会在压力下自己发明抄操作；新教法把抄操作拆成一步，单独教、单独给梯度。

## 5. 可检验的预期变化

验收只认探针与 12 步环（见 `CHUNK5_PLAN.md` §4），不认 loss。预期：

- **Q0 探针**：固定默认被打破（7 个地点不再答同一个），Q0 ≥ 5/7，register 格式 ≥ 5/7。
- **因果探针**：Q0 跟上移动 ≥ 4/7（移动后地点变了，答案跟着变——这是“读当前状态”的直接证据，不是背答案）。
- **12 步环**：Q0 ≥ 2/3，Q3 ≥ 2/3，总分 ≥ 9/12。
- **反指标（说明没学会）**：Q0 仍是 0–1/7 且 7 个地点答同一个固定值；或 loss 明显下降但 Q0 不动（loss 与 Q0 脱钩，s900 已经证明过一次：loss 4.03 的同时 Q2 进步了、Q0 没动）。

## 6. 风险与边界

- **支架格式与旧配置环的桥接器解析**：探针用的 `evaluation/scoring.py` 已核对放行支架格式；旧配置 12 步环的桥接器（二进制）自有 grounded_err 算法，与 scoring.py 不同。若 s1500 探针动了但环不动，先核对桥接器对支架回复的判分，再决定是否调整支架格式——不要直接判定方法失败。
- **答案区掩码是代码改动**：若冒烟失败或 loss 异常，先回退到无掩码跑（只上新数据），不要带着坏代码开整块。见 `CHUNK5_PLAN.md` §2。
- **Q0 探针的生成预算**：探针每题只生成 16 个新 token。支架答案（Q0 约 13 字、Q3 约 11 字）能放下；Q1 不加支架正是因为人物表放不下。
- **不做的事**：不改 s5100 产品版，不动已确认的产品检查点；不用训练 loss 当 Q0 学会的证据；本文只设计，不启动训练（执行见 `CHUNK5_PLAN.md`）。
